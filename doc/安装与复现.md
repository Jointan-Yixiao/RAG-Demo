# 安装与复现

本文说明如何在**新目录、新 Python 3.12 虚拟环境**中安装本仓库、从资料文本重建索引并实际提问。首页的快速开始是本文的精简版。示例目录为 `D:\RAG-Demo`，命令均在 PowerShell 中、仓库根目录下执行。

## 1. 运行要求

| 项 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows x64 | 唯一验证过的平台；锁定文件含 Windows 专用包，其他系统未验证 |
| Python | **3.12**（验证 3.12.14） | 更新的 Python 版本未验证，请不要使用 |
| GPU | NVIDIA，CUDA 12.8 驱动，显存 ≥ 8 GB | 验证卡 RTX 5060 Ti 8 GB；GME fp16 约占 4.1 GB。GME 与 BGE 依次加载，不同时占用 |
| Node.js | 24.x（验证 24.19.0） | 只运行 `scripts/*.mjs` 的提示词桥接，只用内置模块，**不需要 `npm install`** |
| 磁盘 | 建议至少 25 GB 可用 | 参考：GME 快照约 8.3 GB，BGE 约 2.2 GB，另有 PyTorch、pip/Hugging Face 缓存和新索引。实际占用随设备与缓存位置变化，不是测得的最低要求 |
| 网络 | 见第 7 节 | 安装与下载模型需要；重建索引可离线；提问时调用 DeepSeek API |
| 密钥 | DeepSeek API key | 只在 `--execute` 时由现有适配器读取 |

## 2. 仓库里有什么

仓库内容由开发项目按白名单导出，文件清单与 sha256 记录在 `data/metadata/retrieval-eval/experiment-41-final-delivery/release-manifest.json`。

| 内容 | 位置 |
|---|---|
| 运行代码 | `scripts/` 中运行链路用到的 Python 与 `.mjs` 文件 |
| 仍放在实验目录里的已部署代码 | `experiment-16-overlap-split/build_split_index.py`（长块切分规则）、`experiment-22-caption-dedup/claude_caption_dedup.py`（图题去重与检索路由）、`experiment-23-visual-enrichment/claude_enrich.py`（运行时导入）。只有这三个代码文件，不含对应实验数据 |
| 提示词与配置 | `doc/retrieval-*.md`（运行时读取的提示词）、`prompts/`、`config/`、`schemas/` |
| 资料目录与术语 | `data/metadata/documents.json`、`source-identities.json`、`figure-captions.json`、`concept-profiles.json`、`corpus-terminology/vocabulary-draft.json` |
| 原始资料 | `原始资料/` 下 10 份 Markdown，及其引用的 PNG 图片和同名 `.txt` 图片说明 |
| 审核过的非向量输入 | `experiment-41-final-delivery/release-inputs/`（见第 3 节） |
| 测试 | `tests/test_runtime_delivery.py`（19 项，见第 8 节） |

**不包含**：`.env` 与任何密钥、虚拟环境、旧向量索引、切块快照、模型权重、历史实验的运行结果与答案、资料的 PDF/HTML 原件、开发项目的完整测试集。

## 3. 索引如何从文本重建

运行记录由 `scripts/_rebuild_runtime.py records` 从仓库内的文件重新推导，不依赖任何现成的切块或向量：

1. **正文记录（369 条）从原始 Markdown 推导。** 依次运行历史入库用的切块器 `_chunk_corpus.py`、Metadata v2 迁移 `_migrate_chunks_v2.py`（读取 PNG 旁的 `.txt` 说明和 `figure-captions.json`），再按长块规则把超过 1500 个 GME token 的正文二分切开（重叠 240 token）。这一步只需要 GME 的分词器，不加载模型。
2. **图表描述（68 条）是随仓库携带的审核输入。** 它们由模型对照原图撰写，经人工与 AI 审核修订后验收，无法从 Markdown 重新推出，因此以文本形式放在 `release-inputs/visual-descriptions.jsonl`（哈希见同目录 `provenance.json`）。重建时检查每条描述都挂在对应的 Markdown 图片上、`image_path` 一致，前后正文与图题 id 指向重建出的正文记录。
3. **仅供引用的图题 id（24 个）是携带的审核决定**，见 `release-inputs/reference-only-text-ids.json`。这些行可读、可被图表描述引用，但不作为独立候选参与排序。重建时逐条复核：必须仍是单行“图号 + 标题”，并被同文档、同图号的描述声明和包含。

开发项目中已核对：这样重建出的 437 条记录与 E37–E40 实际使用的运行记录一致（id、顺序、正文、元数据；只有不参与排序的 `seq` 重新编号），24 个仅引用 id 也一致。

`encode` 用固定版本的 GME **重新编码**参与排序的 345 条正文和 68 条描述，写成独立的运行索引目录，不读取任何已有向量。E41 实测新旧向量余弦最低约 0.99999976，108 组已保存查询的检索候选与顺序一致。这是同一批资料和固定查询的复现结果，不保证其他设备上 fp16 输出逐位相同。

检索、重排、生成参数与 E40 相同：`hybrid`、K=10、候选上限 20、原生 BGE v2 m3、名次复核开启。

## 4. 安装

### 4.1 获取代码

```powershell
git clone https://github.com/Jointan-Yixiao/RAG-Demo.git D:\RAG-Demo
cd D:\RAG-Demo
```

### 4.2 新建 Python 3.12 虚拟环境

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -VV          # 应显示 Python 3.12.x
.\.venv\Scripts\python.exe -m pip install --upgrade pip
```

不要使用 `--system-site-packages`，也不要复制其他项目的虚拟环境。

### 4.3 先装 PyTorch（CUDA 12.8）

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.11.0+cu128 torchvision==0.26.0+cu128 --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

应输出 `2.11.0+cu128 True`。

### 4.4 再装其余依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-runtime-lock.txt
.\.venv\Scripts\python.exe -m pip check
```

`requirements-runtime.txt` 列出直接依赖及原因，`requirements-runtime-lock.txt` 固定完整依赖闭包。不要额外安装 `sentence-transformers` 6.x：它要求的 huggingface-hub 版本与 GME 所需的 transformers 4.51.3 冲突，而运行链路并不使用它。

### 4.5 检查仓库文件与 Node

```powershell
node --version                            # 24.x
.\.venv\Scripts\python.exe -X utf8 scripts\_prepare_delivery.py check
```

`check` 按发布清单核对每个文件的哈希，在当前环境中导入运行模块，并对全部 `.mjs` 执行 `node --check`。如果报告 `sha256 differs`，常见原因是 Git 在检出时转换了换行符；这时请确认没有开启行尾转换后重新克隆，因为重建记录会读取资料原文的字节。

### 4.6 下载固定版本的模型

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\_rebuild_runtime.py models --download --bge-dir models\bge-reranker-v2-m3
$env:RAG_BGE_MODEL_DIR = (Resolve-Path models\bge-reranker-v2-m3).Path
```

- GME：`Alibaba-NLP/gme-Qwen2-VL-2B-Instruct@9cfa6413f704a7c1cf5064d240748e10c876b286`，存入 Hugging Face 缓存（默认 `%USERPROFILE%\.cache\huggingface`，可用 `HF_HOME` 修改）。
- BGE：`BAAI/bge-reranker-v2-m3@953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`，只下载 6 个运行文件到 `--bge-dir`，逐个核对大小和 sha256 后写入 `download/source.json`。
- 已有同一固定版本的缓存时，可不加 `--download`，命令只做本地核对。**复用缓存时请在自己的验证记录中注明**，因为这不等于空缓存下载验证。
- **从命令行运行 `_rag_e2e.py` 时，每个新的 PowerShell 窗口都要重新设置 `RAG_BGE_MODEL_DIR`**。该变量只从进程环境读取，不从 `.env` 读取。网页启动器会自动识别标准下载目录 `models/bge-reranker-v2-m3`，并将选定路径传给工作进程，因此标准安装下双击启动网页不需要重新设置该变量。

## 5. 重建索引

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\_rebuild_runtime.py records --out data\runtime\records
.\.venv\Scripts\python.exe -X utf8 scripts\_rebuild_runtime.py encode  --records data\runtime\records --out data\runtime\index
.\.venv\Scripts\python.exe -X utf8 scripts\_rebuild_runtime.py verify  --index data\runtime\index
```

- `records`：输出 `records.jsonl`、`reference_only_ids.json` 和 `rebuild-report.json`（各 Markdown 哈希、切分明细、审核输入复核结果）。预期：437 条记录（369 正文、68 描述）、24 个仅引用 id、345 条正文参与排序、10 份文档。任何核对失败都会停止，不会部分写出。
- `encode`：加载 GME，编码 413 条文本；目标目录非空时拒绝写入。E41 在 8 GB 显卡上模型加载约 21 秒、编码约 20 秒。
- `verify`：按运行时方式加载索引，校验哈希、向量、id 与引用关系。

三步都不调用付费 API。

## 6. 提问

```powershell
Copy-Item .env.example .env              # 在 .env 中填写 DEEPSEEK_API_KEY
.\.venv\Scripts\python.exe -X utf8 scripts\_rag_e2e.py --index-dir data\runtime\index --query "向量都找到最像的内容了，为什么还要再排一次？" --out-dir runs\q001-check
.\.venv\Scripts\python.exe -X utf8 scripts\_rag_e2e.py --index-dir data\runtime\index --query "向量都找到最像的内容了，为什么还要再排一次？" --out-dir runs\q001 --execute
```

- **每次都要传 `--index-dir data\runtime\index`**。不传时脚本使用开发项目中的旧版分层索引路径，仓库里没有它，预检会报 `index_error`。
- 不加 `--execute` 只做预检：不读密钥、不联网、不加载模型、不收费。
- 加 `--execute` 才调用 DeepSeek（付费）并加载 GME、BGE。每次用新的 `--out-dir`；已执行过的目录会拒绝重跑。
- 批量：`--queries-file`，格式 `{"queries":[{"id":"q1","original_query":"..."}]}`，每批最多 32 题；示例见 `examples/questions.json`。
- 答案在 `runs\...\07-answers\`。没有生成回答的问题（例如指定了资料目录中没有的文档）也会在这里得到面向用户的说明，这是预期结果，不是程序崩溃。状态含义见 [实时端到端运行说明](RAG-实时端到端运行说明.md)。

## 7. 网络与缓存边界

| 步骤 | 需要网络 | 读取 |
|---|---|---|
| 4.3 / 4.4 安装依赖 | 是（PyPI、PyTorch 索引） | — |
| 4.6 `models --download` | 是（Hugging Face） | — |
| 4.6 `models`（不加 `--download`） | 否 | 本地模型缓存 |
| 5 `records` / `encode` / `verify` | 否 | 仓库文件 + 本地模型缓存（`local_files_only=True`） |
| 6 预检 | 否 | 同上，不读密钥 |
| 6 `--execute` | 是（DeepSeek API） | 密钥；模型仍只读本地缓存 |

模型下载完成后可设置 `$env:HF_HUB_OFFLINE = "1"`，确认运行不再访问 Hugging Face。

## 8. 测试

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

19 项测试覆盖运行索引格式、加载时的拒绝条件、发布白名单和审核输入的哈希，离线运行，不加载模型权重。依赖开发项目旧版分层索引的 1 项在本仓库中**应显示为跳过**；本地 Hugging Face 缓存中没有 GME 分词器时，从原文重建记录的 1 项也会跳过（完成 4.6 后可运行）。

验证报告中的 752 项是开发项目的完整单元测试集，依赖大量历史实验数据，**不随本仓库提供**。

## 9. 与开发项目索引的比较（本仓库中不可用）

`scripts/_rebuild_runtime.py compare` 可比较重建结果与开发项目中 E37–E40 实际使用的索引，并用已保存的计划和查询向量重放检索。它需要开发项目中的旧索引和历史运行记录，这些不随本仓库提供，因此在本仓库中无法运行；E41 的比较结论见 [验证结果](验证结果.md)。

## 10. 已知限制

- 只验证过 Windows x64 + Python 3.12.14 + CUDA 12.8；锁定文件是该平台的依赖闭包。
- E41 的复现在**同一台电脑**的新目录、新虚拟环境中完成：GME 复用了同版本的全局模型缓存，BGE 的 6 个文件复制到新目录并逐个核对哈希；没有借用原环境的包、旧检索向量或历史答案。这不等于另一台电脑、空模型缓存的完整下载验证。
- 三份已部署代码仍在实验目录中，属于位置遗留，不影响运行。
- 68 条图表描述和 24 个仅引用 id 依赖此前的审核，重建只能核对它们与原文的一致性，不能重新产生。新增或修改资料需要重新撰写并审核描述，不在本仓库范围内。
- E40 已知的质量问题仍然存在，见 [WO-008](WO-008-E40端到端完整性与稳定性遗留.md)。
