# Windows 桌面启动器

2026-09-13。`RAG-Workbench.exe` 提供环境检查、初始化、启动和停止服务、打开网页工作台、修复桌面图标。默认模型仍为 GME、BGE v2 m3 和 DeepSeek `deepseek-flash`，准确版本见 [首页模型说明](../README.md#使用的模型)。

## 使用

1. 下载并解压完整项目，或 Git 克隆到准备长期保留的目录。
2. 安装 Python 3.12（含 `py` 启动器）、Node.js 24.x，并满足首页的 NVIDIA 驱动和磁盘要求。
3. 双击 `RAG-Workbench.exe` 或 `启动工作台.cmd`。首次运行自动在当前用户桌面创建“RAG 工作台”快捷方式。
4. 点击“初始化环境”，等待状态更新。程序创建项目 `.venv`、安装固定依赖、下载固定版本 GME / BGE，并在本机建立资料索引。完整环境会直接复用。
5. 点击“打开工作台”，在网页“设置”中填写自己的 API 密钥，然后提问。

初始化不读取 API 密钥，也不调用付费生成接口。提交问题和测试连接使用用户配置的远程接口，由服务商计费。关闭网页或启动器后服务继续保留；用“停止服务”或 `停止工作台.cmd` 结束服务。生成回答或测试连接期间会拒绝停止。

下载 ZIP / Git 克隆只获取文件，不能自动执行程序；**桌面图标在首次运行启动器时创建**。不需要管理员权限。用户删除图标后不会每次打开都强行创建，可用“修复桌面图标”恢复。移动项目后，在新目录运行启动器并修复图标。不要只拷贝 exe，完整项目文件夹必须保留。

## 文件

| 文件 | 用途 |
|---|---|
| `RAG-Workbench.exe` | 可直接运行的 Windows 图形启动器 |
| `launcher/WorkbenchLauncher.cs` | 可审查和重新编译的 C# 5 / WinForms 源码 |
| `assets/app.svg`、`app.png`、`app.ico` | 可编辑图标、预览及 Windows 多尺寸图标 |
| `scripts/_build_launcher.ps1` | 用 Windows 自带 .NET Framework 编译器构建启动器 |
| `scripts/_install_workbench.py` | 离线环境检查和首次初始化 |
| `scripts/_launch_workbench.py` | 启动、识别、复用和停止本目录服务 |
| `data/ui/setup.log` | 初始化输出，疑似密钥片段会遮蔽 |
| `data/ui/setup-result.json` | 初始化结果及完成时间 |
| `data/ui/launcher-state.json` | 本目录是否已经处理过自动桌面图标 |

`data/ui/` 只存于本机，不随 GitHub 发布。

## 实现与保护

- **服务归属**：健康响应须同时匹配服务名称和本目录的 `workspace_id`。标识为绝对目录去末尾分隔符、转小写、UTF-8 编码后 SHA-256 的前 16 位。另一副本占用 8765 时显示占用，不接管或停止它。旧版本缺少标识的服务也视为占用。
- **停止过程**：后端在与提交问题共用的锁中检查工作状态，再标记停止；之后的新提问被拒绝。任务离开队列、尚未启动进程的短暂阶段仍算处理中。
- **快捷方式**：使用 Windows 当前用户桌面路径，支持桌面重定向。写入 `.lnk` 的目标、工作目录与图标。重复执行不重写一致的链接；有效的其他项目链接不覆盖，改用带目录名的备用名称。两个候选名称都冲突时报告错误。
- **初始化范围**：缺少 Python / Node 时提供官方下载页入口，不静默安装系统程序。已安装完整环境直接复用。只在项目范围内写入环境与新索引，拒绝链接目录；不删除不完整环境。旧索引在新索引验证后保留为 `index-before-*`，替换失败时恢复旧索引。
- **取消安装**：初始化子进程置于 Windows Job Object；关闭窗口需要确认，确认后只终止该进程组。正常启动的服务独立保留，不随启动器退出。
- **网络**：环境检查离线执行；初始化从依赖仓库、PyTorch 和 Hugging Face 下载固定文件，并核对 BGE 哈希。启动器不读取密钥或提交问题。

## 构建和测试

已提供编译后的 exe。从源码构建时，在仓库根目录执行：

```powershell
powershell -NoProfile -File scripts\_build_launcher.ps1
powershell -NoProfile -File scripts\_build_launcher.ps1 -Test
.\.venv\Scripts\python.exe -B -X utf8 -m unittest discover -s tests -v
```

构建使用 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（或 Framework 目录），不下载编译器、不修改执行策略。如果组织策略限制本地脚本或可执行文件，请按组织要求处理。

C# 的 21 组离线测试覆盖参数转义、中文路径、目录标识、健康响应、初始化输出、图标冲突与重复运行，以及取消时只停止所属进程树。Python 发布测试共 59 项，覆盖现有运行链路、工作台接口和初始化；跳过条件见首页。

不显示窗口、仅创建快捷方式：

```powershell
Start-Process .\RAG-Workbench.exe -ArgumentList '--install-shortcut' -Wait -PassThru
```

可选 `--shortcut-dir <绝对路径>` 用于隔离测试；该目录必须存在。退出码：0 成功；2 名称冲突；3 失败；64 参数错误。`--no-shortcut` 打开窗口而不处理桌面图标。GUI 模式同目录只允许一个实例，重复打开返回 4。

## 本次验证与边界

- Windows 本机编译成功，21 组 C# 离线测试通过。实际窗口中三个状态卡与主要按钮完整可见，环境和服务识别正确，首次自动创建桌面图标成功。
- 当前完整环境的 `--check` 和 `--install` 复用路径通过，未重新下载模型；启动、停止及已有回答/原图的 HTTP 读取通过。本轮没有新增付费模型调用。
- 原生窗口自动点击工具返回 `call get_window_state before using this window`，刷新后仍未能点击，因此不宣称完成了按钮点击验收。网页浏览器自动验收此前被 Chrome `ERR_BLOCKED_BY_CLIENT` 阻止，仍属已知验证边界。
- 本次没有在另一台电脑、空缓存下完整运行一键下载安装。此前 E41 的新环境安装与索引重建验收验证了底层步骤，不能替代此次初始化界面的完整新机验收。
- 当前固定使用端口 8765，支持单个活动项目。只在 Windows x64 验证，跨平台未实现。
- DPI 为系统级感知；多显示器混合缩放可能略模糊。目录标识不处理 8.3 短路径或联接点别名；请使用普通解压目录。
- 初始化进程启动至加入 Job Object 之间有很短的窗口；若未来发现取消后有残留安装进程，需改为挂起创建后加入 Job。
