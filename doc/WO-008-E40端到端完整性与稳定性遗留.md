题号只用于定位证据和作为回归用例；**不得按题号、文档名或特定 chunk 修改运行逻辑**。不改评分标准、冻结问题与审查结论；不用旧运行的成功覆盖新运行的失败；不再通过调 K 或候选上限凑分。

下文引用的审查记录（如 `reviewer-final-original-a.json`、`reviewer-final-confirmation.json`）和运行名（supplement-v2、confirmation-v3）位于开发项目的 E40 实验目录，未随本仓库发布，这里仅作出处说明。

## 1. 只检索图时缺少正文要点（e39-06）

**问题**：用户问 Gao 综述图 5 中三种检索走法各自怎么运作。规划只发出了一个图表请求，候选和上下文里没有 Iterative Retrieval 的正文段落。

**实际证据**（`reviewer-final-original-a.json`，e39-06）：来源、需求保留、引用依据、图片交付均通过；要点 f1/f3/f4 通过，f2 部分通过。Fig.5 的对应关系讲对了，但冻结要点“依据初始问题和已经生成的文字继续补充上下文”（正文原文 *initial query and the text generated so far*）没有出现。审查定位为检索阶段：只检索了图，未取正文。

**通用改法（待验证）**：当问的是图中机制如何运作（而不只是图上写了什么）时，允许同一需求在保留图表请求的同时追加同来源的正文请求；或在图表候选命中后，按已有的前后正文和图注关联带入相邻正文。二者都需限定预算，并保证纯看图的问题不被正文挤占。

**验收**：图机制题的答案同时覆盖图结构与正文说明；纯图内事实题的图片与描述候选不减少；新增候选记录来源和关联依据；用未参与设计的新图文题验证。

## 2. 上下文已有依据但回答遗漏关键机制（e39-11）

**问题**：候选与上下文完整，回答只说“上下文文档不足时”补查，没有说明由谁、依据什么判断不足。

**实际证据**（`reviewer-final-original-a.json`，e39-11）：候选、上下文完整，答案部分通过，失败阶段为生成。上下文 S3 含 “Documents below the relevance threshold trigger corrective steps”，S1/S5 有 Relevance Evaluation Agent 标记需纠错；回答完全没提相关性评估或阈值。要点 f2（外部补查）通过。

**通用改法（待验证）**：生成规则要求对“什么时候/由什么触发”类子问回答明确的触发条件、判断主体与依据，并在证据有对应内容时引用；可考虑生成前把每个子请求与最相关的证据对应列出，减少遗漏。名次复核（06b）不覆盖这类问题，不应把它扩成未经验证的全答案核验。

**验收**：上下文已含触发机制时，回答写出机制并引用；证据确实缺失时仍如实说明不足、不编造；在未参与调整的新题上比较，不能用回答变长代替要点命中。

## 3. 同一题两次运行召回不稳定（e40-new-02）

**问题**：问 Pinecone RAG 入门中数据进入向量库前的步骤，以及 rerank 一次最多送多少文档。两次真实运行结果不同，最新一次漏掉了切块步骤。

**实际证据**：

- supplement-v2：子请求 req-1 的英文查询为 “What steps must data go through before entering the vector store?”，`rag-guide::text::0011`（Chunk the data）在候选中，向量第 3 名。
- confirmation-v3：req-1 查询变为 “Taking Pinecone's Retrieval-Augmented Generation guide and rerank results together, what steps must data go through before entering the vector database?”。两次来源过滤相同（`rag-guide`、`rerank-results`），检索均为 K=10 + hybrid 上限 20，但 0011 不在候选中。
- `reviewer-final-confirmation.json`：候选、上下文、答案均为部分通过，失败阶段为检索。回答只给出嵌入和入库两步，并如实说明证据未写出分块步骤；rerank 上限子问通过。
- **按最新结果记为部分通过，不以 supplement-v2 的成功覆盖。**

**原因判断的边界**：前置生成的英文子请求从短问句变成带两份文档标题的完整问句，与这次漏召回同时出现，相关性明显；但没有做只替换查询文本的独立消融，不能认定完全由标题前缀造成，前置规划的其他随机差异也可能有影响。

**通用改法（待验证）**：已由来源过滤表达的文档标题不再重复写入检索用英文，或检索时使用去掉来源修饰的子问、同时保留原文用于重排与生成。先用两份已保存查询在同一索引上做离线消融确认因果，再决定是否修改前置规则；对同题多次运行的候选差异做稳定性记录。

**验收**：离线消融给出标题前缀对该证据名次的实际影响；修改后原来源过滤与子请求保留不变；在多道带显式来源的新题上重复运行，比较关键证据召回的一致性，而不只看本题。

## 次要：非目标图片交付过多

e39-06 除用户所问的 Fig.5 外，还交付了 Fig.1/2/3/4/6 共 5 张未请求的图（正确图排第 1）。E41 的 e41-04 也在目标 Figure 1 之外多发了 3 张图。当前 `all_available` 策略会发送候选带入的全部图片，增加成本并可能干扰阅读。属于体验问题，不影响通过判定。后续可在用户明确指定图号时优先或只交付该图，其余保留为文字候选，同时确认不会漏掉用户实际需要的图。

## 次要：来源缺失的用户提示（E41 已完成）

E40 中 e40-new-08 已正确阻塞库外论文，没有用其他资料作答，但内部原因归为“来源有歧义”，也没有可核验的用户提示文本。要求是：给出来源缺失说明，让用户选择提供资料或明确放宽来源，不能自行退回全库；验收需检查用户实际看到的提示，并保留零检索、零生成、未放宽来源的记录。

E41 用同一句用户原话作为 e41-05，在新目录、新环境和新建索引上真实运行：导出了中文来源说明和三项下一步，记录为 `retrieval_performed=false`、`generation_performed=false`、`scope_widened=false`。措辞为“未在当前可用资料目录中找到，或无法唯一确定”，保留了无法区分两者时的不确定性，没有仅凭内部歧义标签断言资料不存在。模型/传输错误、规划器自行产生的来源、实际检索后无候选均有分开的处理与回归检查。详见 [验证结果](验证结果.md)。本项关闭仅指提示交付，不表示所有来源识别句式都已验证。
